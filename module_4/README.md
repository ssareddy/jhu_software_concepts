# Module 4 — Grad Café Analytics: Tests & Documentation

A test-driven, documented Grad Café data analytics service covering scraping,
ETL, PostgreSQL storage, and a Flask analysis dashboard.

## Environment Variables

| Variable | Default | Description |
|---|---|---|
| `DATABASE_URL` | `postgresql://postgres:postgres@localhost:5432/gradcafe_test` | Full PostgreSQL connection string (takes priority) |
| `DB_HOST` | `localhost` | Database host |
| `DB_PORT` | `5432` | Database port |
| `DB_NAME` | `gradcafe` | Database name |
| `DB_USER` | `postgres` | Database user |
| `DB_PASSWORD` | *(empty)* | Database password |

`DATABASE_URL` is checked first. If not set, the individual `DB_*` variables are used.

## Running Tests

Run the full suite from the **repo root**:

```bash
# Linux / macOS
pytest module_4/tests -m "web or buttons or analysis or db or integration"

# Windows (PowerShell) — same command
pytest module_4/tests -m "web or buttons or analysis or db or integration"
```

### Run by marker

```bash
pytest module_4/tests -m web
pytest module_4/tests -m buttons
pytest module_4/tests -m db
pytest module_4/tests -m analysis
pytest module_4/tests -m integration
```

### With coverage

```bash
pytest module_4/tests -m "web or buttons or analysis or db or integration" \
  --cov=module_4/src --cov-report=term-missing
```

### Save coverage summary

```bash
# Linux / macOS
pytest module_4/tests -m "web or buttons or analysis or db or integration" \
  --cov=module_4/src --cov-report=term-missing -q \
  2>&1 | tee module_4/coverage_summary.txt

# Windows (PowerShell)
pytest module_4/tests -m "web or buttons or analysis or db or integration" `
  --cov=module_4/src --cov-report=term-missing -q `
  | Tee-Object module_4/coverage_summary.txt
```

### Test markers

| Marker | Description |
|---|---|
| `web` | Flask route/page rendering tests |
| `buttons` | Pull Data / Update Analysis button behavior & busy-state |
| `analysis` | Label presence and percentage formatting (two decimals) |
| `db` | Database schema, inserts, idempotency, query function |
| `integration` | End-to-end: pull → update → render flows |

### Test doubles / selectors

- **Scraper/loader**: injected via `create_app(loader_fn=...)` — no live network calls
- **Query function**: injected via `create_app(query_fn=...)` — tests use real test DB or mock
- **HTML selectors**: `data-testid="pull-data-btn"` and `data-testid="update-analysis-btn"`
- **Busy state**: observable via `GET /api/scrape_status` — no `sleep()` in tests

### Coverage note

`scrape.py` is excluded from coverage via `.coveragerc`. It uses Selenium with a live
headless browser, and the assignment's SHALL NOT rule explicitly forbids live-internet
tests. All other modules reach 100% coverage.

## GitHub Actions CI

Workflow: `.github/workflows/tests.yml`

The pipeline:
1. Starts a PostgreSQL 15 service container
2. Installs Python 3.11 + requirements
3. Runs the full pytest suite with coverage enforcement
4. Saves the coverage summary to `module_4/coverage_summary.txt`

See `actions_success.png` for proof of a green run.

## Notes for Graders

- All tests run without live internet access — scrapers are fully mocked/injected
- `DATABASE_URL` environment variable controls all DB connections consistently
- The `content_hash` column provides a secondary deduplication key so records
  without a URL are still deduplicated correctly
- Tests are deterministic and complete in seconds, not minutes
